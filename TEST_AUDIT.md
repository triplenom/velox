# Unit test audit — release 334 (Computer Use)

Release 334 adds a per-chat **Computer Use** permission, nine `computer_*` desktop tools and the global **Ctrl+P+End** circuit breaker. No test was deleted. The following tests were updated because the contract they pin changed by request:

- The category tuple and key count now include `("computer_use_enabled", "Computer Use")` (7 keys): `test_appearance_order_and_new_chat_tool_category_labels`, `test_five_way_tool_categories_filter_native_schemas`, `ChecklistToggleTests.test_new_chats_default_off_and_existing_permission_is_not_global`.
- The exhaustive tool-group mapping now routes `computer_*` to Computer Use: `test_file_and_system_toggles_exhaustively_control_their_tool_groups`.
- The chat feature set and locked tool-feature dict include `computer_use_enabled`: `test_chat_feature_model_includes_locked_tool_categories_without_persisted_autoscroll`, `test_first_send_snapshots_history_and_locks_endpoint_and_tool_categories`.
- The composer label now always states `Computer Use: On|Off`: `test_new_chat_settings_uses_a_two_column_three_row_tool_grid`, `test_composer_label_distinguishes_checklists_only_and_no_tools` (which gained On cases).
- The NEW CHAT SETTINGS card draws 7 toggles: `test_new_chat_ui_draws_six_controls_and_actual_click_persists_off`.

The Computer Use Off prompt section is kept short so the existing 13,500-character base-prompt budget (`StallAndProgressTests`, `RunnerPortabilityRegressionTests`) still passes. The limit was not raised.

# Unit test audit — release 328 (config.json)

This release moves all application configuration (settings, endpoint profiles, account credentials) into one `config.json` beside `velox.py`, leaves per-root UI state in `<root>/state.json`, and removes the tests' dependence on the shipped endpoint presets. No test was deleted to make the suite pass; tests whose contract changed were rewritten, and two inventory-only tests were replaced by structural invariants.

## Decoupling from shipped endpoint presets

- Every fixture data root now receives a real `config.json` with a **test-owned endpoint inventory** (`_test_endpoint_profiles()`, `TEST_*_ENDPOINT_ID`) before initialization, exactly as a user's file would be read. The inventory is built only with the public `default_endpoint_profile()` factory, so provider/model-family defaults are still exercised.
- All 332 references to `velox.DEFAULT_*_ENDPOINT_PROFILE_ID` and all uses of `velox.default_endpoint_profiles()` outside one class were replaced. `velox.default_config()` in tests became `_test_config()` (current defaults plus the test inventory). Legacy/saved-endpoint fixtures use test-only IDs.
- `ShippedEndpointDefaultsTests` is now the only place that reads the shipped list. It checks structure only (non-empty, unique IDs, complete normalized profiles, default selections exist, a fresh root starts from them) and contains a guard that fails if any other test references a production preset constant again.
- Removed as inventory-only (replaced by the invariants above): `EndpointDefaultsTests.test_default_profile_inventory_excludes_retired_qwen_presets`, `CurrentEndpointPresetRegressionTests.test_current_inventory_excludes_all_retired_presets`.
- Rewritten to drop shipped-inventory assertions while keeping their behavior checks: `ResponsesAndTaskInspectionTests.test_transport_defaults_and_gpt_profiles` (now uses the factory per model family), `EndpointSettingsAndChatRenderingTests.test_removed_endpoint_providers_and_bundled_profiles`, `GLMFlashProfileTests.test_saved_novita_profile_preserves_complete_transport_defaults`, `GPT6InlineDefaultTests.test_both_bundled_openai_presets_default_to_inline`. Per-profile default checks in `DeadlinePolicyTests`, `ContextPolicyTests`, `EndpointDefaultsTests`, `EndpointRecoveryPolicyTests` and `UnifiedEndpointConfigTests` iterate the fixture inventory instead.

## Configuration layout changes

- Renamed/rewritten for the new contract: `ApplicationTests.test_resource_settings_are_strict_without_additive_fill` → `test_config_file_fields_fill_from_defaults_but_writes_stay_strict` (missing config fields now take defaults; writes remain strict); `test_config_and_app_state_round_trip_inside_app_json` → `..._inside_config_and_state_files`; `test_default_app_json_contains_settings_and_state_only` → `test_default_manifest_combines_settings_and_root_state`; `ConnectorTests.test_connector_credentials_are_revision_independent_xor_files` → `test_connector_credentials_live_in_config_json_beside_unchanged_settings`; `ConfigurationAndConnectorConcurrencyTests.test_credential_read_modify_write_is_thread_safe_and_keeps_xor_payload_valid` → `..._keeps_config_valid`.
- Data-generation rejection tests now edit `state.json` (the root's generation marker) instead of `app.json`; they still verify rejection without writes. `test_legacy_endpoint_settings_are_rejected_without_conversion` and `UnifiedSystemTests.test_root_is_rejected_without_migration` now exercise a legacy `app.json` root and verify nothing is migrated or written.
- Source scans that banned the substring `migrate_` everywhere were narrowed (`migrate_v` for data generations; day/week-chat names for Calendar), because `config.json` now has a deliberate, tested upgrade path.
- Credential tests assert storage in `config.json` (plain JSON, matching the other API keys) instead of XOR files.

## Added coverage

`ConfigFileTests` (13 tests): default location beside `velox.py` and `--config`; complete fresh documents without data-generation tags; a shared external config used by two roots; partial/older documents (missing fields, missing endpoint-profile fields, missing default selections, unknown keys) loading without being rewritten; empty documents and UTF-8 BOM; present-but-invalid values reported without overwrite; malformed JSON; a registered `CONFIG_FILE_MIGRATIONS` upgrade; best-effort reading of a newer `config_version`; state-only writes leaving `config.json` bytes and credentials untouched; automatic migration of a release-327 root (settings, endpoint API keys, state, XOR credentials) including idempotence; keeping an existing shared config; and byte-for-byte rejection of unsupported or corrupt legacy roots. `ShippedEndpointDefaultsTests` adds 4 invariant tests.
